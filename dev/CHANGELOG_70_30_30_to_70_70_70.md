# Change log — 70-30-30 → 70-70-70 cascade integration

All model-script edits are **additive and backward-compatible**, guarded by the
new opt-in flag `run_cascade_70_30_30_to_70_70_70` (or by the presence of an
optional list-column / `wd_outp`). When the flag is absent/FALSE, every edited
code path is byte-for-byte its previous behaviour, so
`00_run_model_cvd_fair.R` (and every other pipeline) is unchanged.

## New files

| File | Purpose |
|------|---------|
| `code/cvd-fair-choices/00_run_70_30_30_to_70_70_70.R` | Standalone isolated runner. Sets the cascade flag, points `model_inputs_file` at the cascade workbook, redirects `wd_outp` to `output/70_30_30_to_70_70_70/`, sets `run_public_health_interventions = FALSE`, runs a fail-fast collision guard, sources Models 01–09, and runs post-run isolation/scope/coverage/collision validation. |
| `dev/README_70_30_30_to_70_70_70.md` | How to run, inputs, outputs, coverage math, diabetes control-rate baseline, isolation. |

## Modified files

### `data/indonesia_70_30_30_to_70_70_70_inputs.xlsx` (input workbook)
- **Appended 18 rows to the `Assumptions` sheet**: the 16 Reference-Case
  BCA/VSL parameters (`bca_base_year`, `bca_discount_rate_primary`,
  `vsl_us_gni_ratio`, `vsl_income_elasticity_preferred`, `vsl_floor_gni_multiple`,
  `vsly_adult_min_age`, `vsly_adult_max_age`, `cost_to_bca_currency_factor`, …)
  plus `economic_perspective` and `downstream_cost_offsets`.
- **Why:** Model 08 reads BCA parameters from the *active* workbook's Assumptions
  sheet and stops if any are missing; the cascade workbook did not carry them.
  Values are copied verbatim from `indonesia_model_inputs.xlsx` (single shared
  BCA transfer basis, Robinson et al. 2019), so the isolated run is
  self-contained and does **not** silently fall back to the clinical workbook.
- **Safe:** all 15 sheets preserved; only new `Assumptions` rows added.

### `code/cvd-fair-choices/04_define_interventions_indonesia.R`
- **Added `.build_cascade_catalogue()`** — a dedicated reader for the bespoke
  cascade workbook that emits `fair_scenarios` (baseline + the single
  `S_70_30_30_TO_70_70_70`) and `fair_inputs` in exactly the shapes Models 06/09
  consume. It parses the standard-schema `Intervention_Cause_Map` / `Effect_Sizes`
  / `Cost_Components` sheets, reads the per-year effective-coverage path verbatim
  from `Coverage_Trajectory`, splits effect rows by sex (Men→Male, Women→Female),
  attaches an exact per-year `coverage_path` list-column, reconciles against the
  workbook's `Model_Input_View` transition multipliers (hard FAIL on any
  mismatch), builds the cost catalogue with the cascade coverage path, and stashes
  a `fair_inputs$cascade` bundle for Model 09's cascade sheets. Asserts the
  catalogue is exactly `{baseline, S_70_30_30_TO_70_70_70}`.
- **Wrapped the catalogue-builder call** so `run_cascade_70_30_30_to_70_70_70 == TRUE`
  routes to `.build_cascade_catalogue()`; otherwise the unchanged
  `.build_fair_catalogue()` runs.
- **Why / safe:** the cascade workbook's Coverage/Assumptions sheets are a
  milestone-cascade format the FAIR reader cannot parse; a separate reader keeps
  `.build_fair_catalogue()` untouched. The branch defaults to the ordinary reader.

### `code/cvd-fair-choices/06_run_scenarios_indonesia_fair.R`
- **`calculate_fair_workbook_impact()`**: added an optional per-row per-year
  coverage-path override. When an effect row carries a `coverage_path`
  list-column, its exact per-year effective coverage replaces the internally
  computed linear ramp; the FAIR incremental-effect formula and `baseline_coverage`
  anchor are otherwise unchanged. Absent on every standard workbook → identical
  behaviour.
- **End-of-model cascade scope guard** (guarded by the flag): asserts every
  modeled row's scenario id ∈ `{baseline, S_70_30_30_TO_70_70_70}`.
- **Why:** the cascade's piecewise (2030-kink, no-backsliding) coverage path is
  not expressible as the single linear baseline→target ramp the engine assumes;
  injecting the exact path lets R reproduce the workbook to machine precision.
- **Safe:** additive, guarded by column presence / the flag.

### `code/cvd-fair-choices/08_economic_value_calculation.R`
- **`DIR_OUT`** now honours `wd_outp` when supplied
  (`DIR_OUT <- if (exists("wd_outp")) sub("/+$","",wd_outp) else file.path(wd,"output")`).
- **Why:** Model 08 previously hard-coded `file.path(wd, "output")`, which would
  have read the cascade's Model 07 outputs from — and written Model 08 outputs to
  — the ordinary directory, breaking isolation.
- **Safe:** in an ordinary run `wd_outp` already equals `…/output/`, so
  `DIR_OUT` resolves to `…/output` exactly as before.

### `code/cvd-fair-choices/09_cost_value.R`
- **Cost loop**: added an optional per-record per-year cost-coverage override
  (mirrors the Model 06 change), so cascade costs use the same exact effective-
  coverage path as the health effects. Absent → the standard linear `cov_path` is
  used unchanged.
- **Annual_Cost formula tie-out** (cascade only): the Excel `Annual_Cost`
  coverage column normally recomputes a linear ramp; for the cascade it is
  replaced with the R-source per-year effective-coverage the engine actually used
  (like the other R-source input cells), so the Excel cost / budget / CEA totals
  reconcile to the R engine (resolves the Excel-vs-R discounted-cost and
  cost-per-death QA checks). Guarded; ordinary runs keep the live linear-ramp
  formula.
- **Formula workbook**: added a flag-guarded block that appends three
  cascade-specific sheets — **`Cascade_Assumptions`** (the editable cascade inputs
  and their source cells, incl. the diabetes control-rate baseline),
  **`Cascade_Trajectory`** (per intervention × sex × year: baseline coverage,
  2030/2040 targets, milestone components with the half-effect, the exact per-year
  effective coverage, an Excel `effective_from_components` reconstruction, and the
  live `model_effective_coverage_used` the engine applied), and **`Cascade_QA`**
  (Excel formulas reconstructing the 0.1365 / 0.4165 milestones and recording the
  R-side reconciliation vs `Model_Input_View`) — and registered them in the sheet
  order. Existing standard sheets are neither renamed nor merged.
- **Why / safe:** guarded by `run_cascade_70_30_30_to_70_70_70` and by
  `!is.null(fair_inputs$cascade)`; an ordinary clinical run produces a
  byte-for-byte unchanged workbook.

# 70-30-30 → 70-70-70 cascade run — README

An **isolated** run of the Indonesia NCD pipeline (Models 01–09) for the
hypertension/cholesterol + type-2-diabetes treatment cascade that scales the
national cascade from **70-30-30** (70 % diagnosed, 30 % of diagnosed treated,
30 % of treated controlled) by **2030** to **70-70-70** by **2040**, held
thereafter.

It reuses the existing FAIR-Choices model scripts unchanged in behaviour; the
only differences from an ordinary run are (a) a different input workbook, (b) a
dedicated catalogue builder, and (c) a dedicated output directory. It **cannot**
affect, append to, or overwrite any ordinary clinical / public-health / combined
output.

## How to run

From a fresh R session (the runner begins with `rm(list=ls())`):

```r
source("code/cvd-fair-choices/00_run_70_30_30_to_70_70_70.R")
```

or from a shell:

```bash
"C:/Program Files/R/R-4.5.1/bin/Rscript.exe" code/cvd-fair-choices/00_run_70_30_30_to_70_70_70.R
```

The runner runs Models 01–09 in order (Model 10, the clinical validation, is
intentionally skipped). Calibration (Model 03) and the parallel projection
(Model 06) make a full run take several minutes.

## Which input workbook it uses

`data/indonesia_70_30_30_to_70_70_70_inputs.xlsx` — a **bespoke cascade
workbook** (not the clinical `indonesia_model_inputs.xlsx`). Everything the run
needs is read from it:

| Sheet | What is read |
|-------|--------------|
| `Assumptions` | analysis years, first/final target years, exact effective-coverage milestones, half-effect fraction, no-backsliding flag, discount rates, price year, currency, **and the 18 Reference-Case BCA/VSL parameters** (added so Model 08 is self-contained) |
| `Intervention_Cause_Map` | the 6 included links (`include_flag = 1`) for `I_CVD_PRIMARY` (IHD/IS/ICH/HHD incidence) and `I_T2D_TREATMENT` (T2D direct mortality + IHD-via-high-blood-glucose case fatality) |
| `Effect_Sizes` | per-link `effect_value`, `affected_fraction`, age band, sex |
| `Coverage` | the milestone cascade decomposition (diagnosis × treatment × control, treated-but-uncontrolled share, controlled share, half-effect → exact effective coverage) |
| `Coverage_Trajectory` | the authoritative **per-year effective-coverage path** (`scenario_effective_coverage`) per intervention × sex, with the 2030 kink, cholesterol-follows-hypertension, and no-backsliding already baked in |
| `Cost_Components` | screening + hypertension/statin treatment costs and the **diabetes** screening / non-insulin / insulin costs |
| `Model_Input_View` | the workbook's own reproduction of the per-(link, sex, year) `transition_multiplier` — used as the exact reconciliation target |

Nothing (no cascade %, unit cost, or discount rate) is hard-coded in R.

## How exact effective coverage is calculated

For each risk factor × sex × milestone:

```
treated_share            = diagnosed × treated_conditional          (e.g. 0.7 × 0.3 = 0.21 in 2030)
controlled_share         = diagnosed × treated × controlled         (e.g. 0.7 × 0.3 × 0.3 = 0.063 in 2030)
treated_uncontrolled     = treated_share − controlled_share         (0.21 − 0.063 = 0.147)
effective_coverage       = controlled_share + partial × treated_uncontrolled
                         = 0.063 + 0.5 × 0.147 = 0.1365   (2030)
                         = 0.343 + 0.5 × 0.147 = 0.4165   (2040)
```

`partial = treated_uncontrolled_effect_fraction = 0.5` (treated-but-uncontrolled
patients receive half the treatment effect). Between milestones the effective
coverage is interpolated **piecewise-linearly** (linear 2025→2030, then
2030→2040), held flat after 2040. The **no-backsliding** rule keeps the coverage
at its measured baseline where that baseline already exceeds a milestone (this is
why, e.g., diabetes for women holds flat 2025→2030 rather than dropping to
0.1365). The pipeline reads this per-year path **verbatim** from
`Coverage_Trajectory$scenario_effective_coverage` and applies it through the
FAIR-Choices incremental-effect formula, so R reproduces the workbook's
`Model_Input_View$transition_multiplier` to machine precision.

## How to change the diabetes control-rate baseline

Edit **`diabetes_baseline_control_among_treated`** on the `Assumptions` sheet of
`data/indonesia_70_30_30_to_70_70_70_inputs.xlsx` (currently ≈ 0.3421, derived as
6.5 % controlled / 19.0 % treated in the 2023 national diabetes cascade; sourced
to Muharram et al. medRxiv 2026). The workbook's `Coverage` /
`Coverage_Trajectory` / `Model_Input_View` sheets recompute the diabetes baseline
effective coverage from it; then re-run the runner. The value is also surfaced
(read-only, with its source cell) on the `Cascade_Assumptions` sheet of the
formula workbook.

## How isolation from the other interventions is enforced

* A **new opt-in flag `run_cascade_70_30_30_to_70_70_70`** (set only by this
  runner) routes Model 04 to `.build_cascade_catalogue()` and arms the additive
  cascade branches in Models 06 and 09. The ordinary runner never sets it, so
  every edited script is byte-for-byte its old self there.
* `run_public_health_interventions = FALSE`, so no public-health or combined
  scenario/workbook is built.
* The catalogue is asserted (in Model 04 **and** in the runner) to contain
  **exactly** `{baseline, S_70_30_30_TO_70_70_70}` — no other clinical / PH /
  combined scenario.
* After Model 06 every modeled row is asserted to carry one of those two
  scenario ids.
* `wd_outp` is redirected to `output/70_30_30_to_70_70_70/`; every Model 06–09
  output honours it (Model 08's previously hard-coded `DIR_OUT` now honours
  `wd_outp` too).
* A **fail-fast collision guard** runs before any model: it asserts every
  resolved cascade output path is under `output/70_30_30_to_70_70_70/` and equals
  no ordinary output path, and it snapshots the ordinary outputs' modification
  times so the post-run validation can prove none was touched.
